# NADIN V8

V8 retains NADIN's original grey/yellow surfaces, blue links and dense tabular presentation.

- GigReps, archived GigReps and recordings have one integrated contextual sidebar. The old `rendergiglistontheleft` switch and recurring layout timers are removed. Existing installations can keep the obsolete configuration entry; it is ignored. `ifleftthenthiswidth` still controls the desktop width, within 120–450px.
- At widths up to 700px the same sidebar opens over the content using the menu button. Escape and tapping outside close it. Desktop navigation remains visible.
- Mobile tune rows remain single-line. Their Open menu contains the original PDF, recording, Info, more and management actions. Original nodes and event handlers are retained when switching screen sizes. The menu also shows the full tune title.
- Mobile information and bulk downloads start collapsed. Explicitly opening either reveals its full content. Top navigation uses short labels on phones.
- Recording dates use the same sidebar. Recording URLs now resolve to their actual tune directory; durations include all groups and use minutes × 60 + seconds.
- Library sorting and its export links remain functional. The editor retains its existing windows and controls, with space reserved for the library beside them.

Deploy the changed/new source files, including `nadinmodule/ui.inc.php` and `nadinmodule/layout.js`. Preserve installation-specific configuration, users, library media and GigReps. No data migration is required.

Validation: PHP 8.3 syntax checks across index/configuration and 73 module PHP files; Chromium at 320, 390, 768 and 1440px for current GigReps, archive, recordings and library; sidebar open/close without content displacement; per-tune menu bounds, PDF links, expanded more content, desktop/mobile restoration; library alpha/newest sorting; editor frame rendering. No JavaScript exceptions were observed. Checks used a disposable fixture with synthetic users. Native Safari/iOS has not been exercised.

forScore backport: export links use the existing print/XLS link group in current and archived GigReps and the library. Export uses the corrected V9 service, including automatic heading placeholders, section/Parts selection and stable PDF identities. See [forScore workflow](forScore.md). No version renumbering or data migration.
