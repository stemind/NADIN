# NADIN 7.7 — classic interface and forScore

This consolidated 7.7 release includes the classic CSS-based GigRep layout and all forScore corrections from the earlier patch sequence. It replaces the earlier 7.7 release and its patch releases. There is one update package: **NADIN-7.6-to-7.7.zip**. The classic release source is maintained on `7.7.2-css-gigrep-layout` (the branch retains its historical name). The separate V8–V18 design stages remain separate development lines.

## GigRep position

The same rule applies to current and archived GigReps in every maintained branch:

| `rendergiglistontheleft` | List position |
| --- | --- |
| `'yes'` | Left vertical column (default) |
| Missing or empty | Left vertical column |
| Any other value except the literal string `'no'` | Left vertical column |
| `'no'` | Above the tunes |

`ifleftthenthiswidth` continues to control the column width. The classic release uses CSS instead of a recurring layout timer. Each development line retains its responsive design and mobile navigation. No configuration edit is needed to obtain the default.

## forScore workflow

1. Open forScore in a new tab from a current GigRep or the archive. The media Library has no forScore link. **Back to NADIN** closes that tab and reveals the unchanged original NADIN view. The wording stays the same. Directly opened export pages, or browsers that refuse to close, use the normal NADIN link as a fallback. The page title and heading show the task name without a release number. Choose your section; Parts remains the permitted fallback when section notes are unavailable. The section is remembered for one year in this browser, separately for each installation and account, and checked against current permissions.
2. Choose a first NADIN import with PDFs, an update using a fresh forScore Filename inventory CSV, or a setlist-only export. Section, import and CSV changes refresh automatically. Without JavaScript, use **Update selection**. Inventory content and first-import confirmation are not saved as preferences.
3. A single matching PDF is selected automatically. Multiple candidates or revisions require a choice. Literal headings keep their text and position without PDF warnings or piece numbers. Actual missing notes require explicit placeholder confirmation. Repeated tunes keep their positions; each new PDF is embedded once.
4. The primary **Download forScore setlist (.4ss)** action and its summary are at the top, before setup and the tune list. The same action is also available below the tunes. Both buttons share the complete form and stay active. They use an explicit NADIN-blue design with readable white text, a download symbol and visible hover/keyboard-focus states, including in the classic interface. An incomplete choice scrolls back to the first obligatory field, focuses it and displays its validation message. The optional **Import and updates** help is separated from the download action. During an automatic refresh the page announces that the selection is still being updated.
5. Open the download in forScore. A download does not establish that an import succeeded. Use a fresh inventory from the actual destination library for updates so existing PDFs and annotations can be reused. Replacement with a newer PDF revision remains an explicit choice.

The standalone page sends an explicit UTF-8 response header and loads the installation's own `favicon.ico`. Source Reps and PDFs are not converted or renamed. Server checks for permissions, CSRF, stale previews and source-file integrity remain in force. The updated client script and scoped action stylesheet use fresh asset URLs while the displayed release remains 7.7.

Stable identities are stored in `.nadin-forscore.json` and `.nadin-forscore.lock` in tune folders; include these files in backups. Unambiguous folder/PDF renames retain their identities; copied arrangements receive independent identities. Corrupt identity metadata blocks export. The web-server account needs the existing Library write permissions and temporary storage. Inventory uploads are limited to 5 MB and embedded PDFs to 150 MB; server limits may be lower. Native iPad import remains a separate acceptance check.

## Verification

`tests/gig-defaults-http.py` runs authenticated real-PHP/Chromium checks for both roles, current/archive views and `yes`/`no`/missing/empty/other settings in all fourteen branches. Existing layout checks also cover configurable widths, responsive behaviour and JavaScript-disabled operation. The classic CSS suite exercises long-list scrolling, navigation and reopened archive information.

The exporter regression and real HTTP/browser suites cover headings, order, repeated tunes, section/Parts permissions, PDF identities and revisions, inventory updates, actual downloads from both actions, required-field focus from both actions, no-JavaScript fallback, the favicon and narrow windows. Real tab tests cover current GigRep and archive: the original NADIN URL and scroll position survive section/import refreshes, an actual download and closing with **Back to NADIN**. They also check error-page return, direct entry and a browser refusing to close. At 1200, 390 and 320 px, the primary action is checked in the initial viewport before setup and tunes, with explicit styling, sufficient text contrast, a 44 px touch target and keyboard focus. Top and bottom downloads are checked for identical exported bytes. The 7.6 update ZIP is applied to a disposable baseline and its application files compared with the tested release source.

Run the PHP checks with `php tests/forscore.php`; select PHP for the HTTP suites using `NADIN_PHP=/path/to/php`. Browser checks require Node Playwright and Chromium (`NADIN_CHROMIUM`). Enable full workflow checks with `NADIN_WORKFLOW_DOM=1 NADIN_WORKFLOW_BROWSER=1 NADIN_BROWSER_TESTS=1 python3 tests/forscore-http.py`. Tests use synthetic local fixtures and send no email.
