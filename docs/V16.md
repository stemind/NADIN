# NADIN V16 — PHP compatibility preparation

V16 is based on the reviewed, renumbered V15. It keeps NADIN's compact interface, file formats, optional federation, simple initial-password onboarding and personal passwords.

## What changed

- Replace the deprecated `utf8_decode()` filename conversion with explicit UTF-8 → ISO-8859-1 conversion. German accents, existing ASCII names and removal of unsupported characters keep their previous results. The hosting's multibyte substitution setting is restored after each conversion.
- Initialise per-list counters, duration totals, section lists and optional form/query/cookie values. Empty gigs, missing tune information, media forms, print/CSV exports and preview pages work with strict error handling.
- Release PHP 8 `CurlHandle`/`GdImage` objects without deprecated close/destroy calls. The bundled legacy FPDF receives a real constructor, retaining explicit old constructor calls, and loses obsolete runtime-magic-quotes and line-ending INI calls. It is not replaced with a different PDF engine.
- Remove obsolete password-cookie refreshes and retired ZIP-refresh iframes from media editors. The current session refresh and fingerprint-based ZIP generation remain in use.
- Run the same permission checks before HTML output, including archive's two existing rights, so denial returns HTTP 403 even without output buffering. No new rights are granted.
- Encode the saved scroll target as JavaScript data rather than executable text.

Existing authentication storage names, salts, CSRF scopes, setlists, media filenames, caches and sessions are not migrated. The subsequent [popup design alignment](popup-design.md) applies the existing interface to the editor windows and file dialogs.

## Hosting and deployment

**PHP's `mbstring` extension is required for filename conversion.** Check that it is enabled before upgrading. It is now explicit in `composer.json`; local-only installations also need it. This avoids relying on deprecated core conversion functions while preserving the old single-byte mapping.

Preserve the installation's `config.inc.php`, existing `userdatei` data, federation configuration, media and hosting-specific mail adapter. Deploy application files using the existing upgrade procedure. For optional SAML/OIDC, run `composer install --no-dev` with the committed lock file and the [V15 federation check](V15-federation.md). Local sign-in remains independent of Composer.

## Verification

On 31 October 2026, the full suite passed **622 checks** on both:

- PHP 8.3.6 (regression baseline).
- PHP 8.5.12 with the future-error simulation enabled.

Each run also linted **157 PHP files**. Coverage includes authentication and recovery, brute-force throttling, role restrictions, gig/user administration, legacy single-byte filenames, real TLS and signed SAML/OIDC fixture flows, forScore, ZIP integrity/concurrency, uploads, duration changes, print/CSV exports and the administrative DOM interactions. The bundled TrueType font conversion also completed in an isolated directory. All accounts, providers, media mutations and outgoing-mail adapters in these tests are synthetic; no production IdP or mail delivery was tested.

Reproduce with Python packages `requests`, `beautifulsoup4`, `cryptography`, Node with `jsdom`, the PHP extensions used by the application, and installed Composer dependencies:

```sh
python tests/check-runtime.py --php /path/to/php8.3
python tests/check-runtime.py --php /path/to/php8.5 --simulate-php9
```

The runner disables opcode caching only in its disposable test processes so rapid fixture/config changes are visible. It never changes hosting settings. The simulation promotes deprecations, undefined variables, missing array keys and uninitialised offsets to exceptions even when application warnings are suppressed; it also disables the removed/deprecated calls addressed in V16. Missing keys/offsets are an additional strictness check, not a claim about the final PHP 9 specification.

## PHP 9 status and remaining gate

This is **PHP 9 preparation, not a native PHP 9 certification**. PHP 9 has not been released as of the verification date. The implementation addresses the accepted removal of `utf8_encode`/`utf8_decode`, undefined-variable error promotion, null-to-non-nullable scalar calls and current PHP 8.5 deprecations encountered in NADIN.

The locked `firebase/php-jwt` 7.2.1 package still declares `php: ^8.0`. The application's current PHP constraint is deliberately retained. Do not bypass Composer platform checks to install federation on PHP 9. Once PHP 9 and compatible dependency releases are available, update the constraints and lock file, then run the same suite on the actual runtime and verify the production identity provider and mail transport before deployment. Unannounced future engine changes cannot be certified today.
