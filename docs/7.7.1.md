# NADIN 7.7.1 — resumable MP3 playback

The classic 7.7.1 maintenance release adds correct MP3 byte-range delivery. After an interrupted download, a browser can request the remaining recording instead of receiving the beginning again. Login and file permissions are checked before every full or partial response. The source branch retains its historical name, `7.7.2-css-gigrep-layout`.

## Installation

Back up the installation before updating. Extract the update at the NADIN root and preserve its subdirectories.

| Installed version | Package |
| --- | --- |
| Consolidated classic 7.7 | `NADIN-7.7-to-7.7.1.zip` — replaces `get/file.php` and `login.php`, adds `get/stream.inc.php` |
| Classic 7.6 or an earlier 7.7 patch snapshot | Apply the preceding consolidated 7.7 update from the [7.7 guide](7.7.md), then the three-file 7.7.1 patch |
| New installation | Complete source archive for tag `v7.7.1`, with normal installation setup |

Verify the package against `SHA256SUMS.txt`. Install the MP3 controller and helper together. Keep configuration, salt, accounts, recordings, GigReps, attachments, hidden forScore metadata and existing permissions. The small 7.7 patch preserves a customised `nadinmodule/infos.inc.php`; see the [7.7 guide](7.7.md) before applying the preceding cumulative update to an installation with a customised calendar connection.

Development lines V8–V18 and the maintained baseline receive the equivalent repair in their own controllers. Use that branch's own files, preserving its authentication and interface.

## Validation and limits

The [MP3 transport report](MP3-STREAMING-2026-11-26.md) records 1,008 passing HTTP checks across all 14 maintained branches, including actual 130-second MP3s and independently measured complete reconstructed downloads. The classic source also passes its existing parity, media and forScore checks.

This corrects the demonstrated resume defect; it is not proof of the exact cause of a specific hosting timeout. If playback still stops, check the hosting logs and the browser on the actual installation. Local Chromium playback, native Safari/iOS and hard provider timeouts were not validated by these passing HTTP checks.
