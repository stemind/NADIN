# NADIN 7.7 — 7.6 plus forScore

This release starts directly at tag `v7.6` (`8f66ee17444d03ef01aacc1c8c39de3101364234`). It adds the optional forScore export without taking over the redesign or other changes from V8–V16.

Exactly two existing files change: `nadinmodule/gigreps.inc.php` and `nadinmodule/library.inc.php`. Each receives one forScore link directly below the existing Print link, using the same inline style and new-tab target. Archived Reps share the existing GigRep view and therefore receive the same link. Every other existing file, including configuration, authentication, stylesheet, navigation, editors, Print and XLS code, remains byte-for-byte unchanged.

The new `get/forscore.php` endpoint authenticates the existing 7.6 cookie session and checks the existing account, expiry, section, archive, library, Score and hidden-file permissions. The exporter and its text/Rep helpers are isolated in `nadinmodule/forscore.inc.php`; no global UI or authentication migration is introduced.

## Musician workflow

1. Choose forScore below Print in the current Rep, archive or library. Choose your section; Parts is the fallback when section notes are unavailable. Ambiguous PDF choices require a selection.
2. For a first import, choose the export containing missing PDFs and confirm that this is the first NADIN import into that forScore library. Otherwise upload a fresh forScore library metadata CSV containing the Filename column. The CSV is used for this review and download; it is not saved to the server.
3. Download the `.4ss` file and open it in forScore. Open Setlist XML references work with forScore 12 or later; embedded PDF data requires forScore 14.3 or later. See the [official format](https://forscore.co/developers-file-types/).
4. For subsequent Reps or updates, supply a fresh CSV from the actual destination library. Unchanged files are referenced; each new PDF is embedded once, even if the tune occurs repeatedly. Existing annotated versions stay selected when identified; replacing them with a newer revision is an explicit choice. A download does not establish that an import succeeded. Stale inventories or custom file renames can prevent matching.

Headings are automatic text placeholders, in their original position and with their original text. They receive no piece number, PDF, missing-notes warning or confirmation requirement. Blank source lines remain ignored. A real library entry with inaccessible/missing notes still requires explicit placeholder confirmation. Existing Reps and PDFs are not rewritten. The legacy Rep format cannot distinguish a deleted tune folder from a free-text heading; such text remains a heading for review.

Stable file identities are written to `.nadin-forscore.json` and `.nadin-forscore.lock` inside each exported tune folder. Keep them in backups. Folder/PDF renames retain identities where unambiguous; copied arrangements receive independent identities. Changes to source PDFs produce revision filenames. Corrupt identity metadata blocks export without regenerating identities. The web-server account needs the existing library write permissions and PHP temporary storage. Inventory uploads are limited to 5 MB; embedded PDFs to 150 MB. Server upload/post limits can be lower.

## Verification

Run `php tests/forscore.php` for 62 regression checks and `NADIN_PHP=/path/to/php python3 tests/forscore-http.py` for 49 actual HTTP checks in a disposable installation. The tests use synthetic identities and PDFs and send no mail. The HTTP suite can additionally run real Chromium checks with `NADIN_BROWSER_TESTS=1`; provide Playwright via Node and optionally select `NADIN_CHROMIUM`.

Validation covers headings/escaping/order/repetitions, section/Parts fallback, existing/revised/renamed/copied PDFs, inventory upload, binary PDF bytes, stale previews, source access, permissions, CSRF, unsafe paths and metadata, and the Print-style links in current/archive/library views. The new and modified PHP files parse on PHP 8.3 and 8.5. Native import into the forScore iPad app remains a separate acceptance check.

The upgrade ZIP replaces only the two link-bearing files and adds the exporter, documentation and tests. Preserve your installation configuration and data. A production installation is not modified by this GitHub release.
