Current interaction and cookie behaviour: [forScore workflow](forScore-workflow.md). This supersedes the manual Review steps below.

This line starts at `v7.6` (`8f66ee17444d03ef01aacc1c8c39de3101364234`) and keeps its original interface, authentication and file model. The optional forScore link sits directly below Print in current and archived GigReps. The Library retains Print/XLS without a bulk forScore link.

## Musician workflow

1. Open forScore from a GigRep and choose your section. Section changes refresh the selection automatically; Parts is the fallback when section notes are unavailable.
2. Choose one import option: **First NADIN import – include PDFs**, **Add to existing notes – use inventory CSV**, or **Setlist only – no PDFs**. First import needs no CSV. For subsequent imports containing PDFs, export a fresh Filename metadata CSV from forScore's Backup panel and select it here. The upload automatically refreshes the suggestions, and the loaded filename stays visible.
3. Resolve any ambiguous PDF choices, download the `.4ss` and open it in forScore. Existing identified PDFs and annotations are reused; a source revision remains an explicit choice. Reference-only exports contain no PDF data and need no CSV. Without JavaScript, use **Update selection** after changing fields.

The [official Open Setlist format](https://forscore.co/developers-file-types/) supports references from forScore 12 and embedded PDFs from 14.3. Embedded PDF data is written under a collision-free filename, so unconditional embedding can create duplicates. A fresh destination inventory is required for subsequent PDF-inclusive exports. Downloading is not proof of importing; stale inventories or renamed files can prevent matching.

Headings are automatic text placeholders in their original positions and exact text, including ordinary slash-separated text. They have no tune number, missing-note warning or confirmation. Repeated tunes keep their positions; each PDF is embedded once. Blank lines remain ignored. A real empty/inaccessible library tune requires explicit placeholder confirmation. The legacy format cannot distinguish a removed tune folder from an ordinary text heading.

Stable identities are stored in `.nadin-forscore.json` and `.nadin-forscore.lock` inside each exported tune folder. Preserve them in backups. Unambiguous folder/PDF renames retain identities; copied arrangements receive independent identities. A changed PDF gets a revision filename. Corrupt metadata blocks export rather than silently replacing identities. No CSV is persisted: its filenames are returned in the form for the next request. Limits: 5 MB inventory, 150 MB embedded PDFs; hosting upload/post limits can be lower.

## Patch changes and deployment

7.7.1 corrected a legacy hosting `charset=latin1` response by explicitly sending `Content-Type: text/html; charset=UTF-8`. 7.7.2 includes that correction, the automatic workflow, Library-link removal, matching PHP-rendered version labels, and reliable server-rendered GigRep placement. `$rendergiglistontheleft='yes'` puts the list at the left; `'no'` puts it above the tunes. `$ifleftthenthiswidth` still supplies the sidebar width. Current and archived lists use the same configuration path. The duplicate archive layout script is removed; selected-gig highlighting and archived-info collapse remain.

Use the **7.7/7.7.1 correction ZIP** for an existing 7.7 installation, or the **7.6 upgrade ZIP** from 7.6. Replace all included files at their relative paths, including the new `nadinmodule/forscore.js`. Preserve the installation's `config.inc.php`, salt, members, music, Reps, attachments and hidden identity metadata. The packages do not contain production data or replace configuration. Original release tags remain unchanged; `v7.7.2` is the new patch release.

## Verification

`php tests/forscore.php` checks export identities, headings, order/repetition, inventories, source revisions and permission/path rejection. `NADIN_PHP=/path/to/php python tests/forscore-http.py` exercises real forms/downloads under disposable accounts; choose a server charset with `NADIN_DEFAULT_CHARSET`. `NADIN_WORKFLOW_DOM=1` also checks automatic changes, fallback controls and pending-state handling using Node/jsdom. `tests/gig-layout-http.py` checks config combinations and software-DOM adaptation; `tests/main-parity-http.py` checks the common Main behaviour contract.

The current phase verifies PHP 8.3/8.5, real HTTP and software DOM. Native browser layout and forScore/iPad import remain acceptance boundaries. No production installation, user, music or mail delivery is changed by this source release. Cross-branch findings are documented in [the maintenance review](2026-10-31-maintenance.md).
