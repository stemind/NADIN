# NADIN V15 — optional federation, reliable ZIP downloads and regression fixes

<img src="../nadin.svg" width="64" height="64" alt="NADIN V15 logo">

V15 builds on V14 without changing the familiar compact layout or the local onboarding process. Federation is **off by default**. Existing initial passwords, personal passwords, recovery, expiry dates and V12 brute-force protection remain available.

## Optional organisation login

An installation can enable OpenID Connect, SAML 2.0, or both. Enabled providers add one compact button each to the login page. A verified external identity must be explicitly assigned to an **existing, active NADIN account**. NADIN's local permissions remain authoritative; email, group or administrator claims from the identity provider cannot create accounts or grant permissions.

See [the setup guide](V15-federation.md) for dependencies, callback URLs, mapping and operational checks. No external provider is enabled or configured by this release. The signed protocol flows have been tested against isolated HTTPS fixtures, not a real organisation's production identity provider.

## ZIP downloads

- Current and archived setlists have separate cache identities and explicit download links, even when legacy files have the same gig name.
- File contents, names, sizes and setlist membership determine the cache. Replacing a PDF while preserving its timestamp and size still refreshes the ZIP.
- New archives are built to temporary files. Their embedded bytes are verified before publication. Damaged archives or manifests are rebuilt automatically.
- Multiple requests for the same archive share a lock. Source selection waits for NADIN's administration/media writes. The response opens the archive **before** releasing the locks, so a subsequent rebuild cannot remove a download that has already started.
- Section PDFs take precedence; readable, nonempty Parts PDFs fill gaps. Repeated tunes do not duplicate files. Literal brackets, Unicode and legacy Windows-1252 names are handled. Hidden, deleted, ambiguous, symlink and empty files are excluded.
- ZIP switches and section/archive rights are checked on the server, including direct URLs. Audio is stored without unnecessary recompression.

Storage exhaustion, inaccessible files, a lost network connection or continuously changing FTP uploads cannot be made impossible. NADIN fails clearly instead of serving an incomplete archive; unstable sources return HTTP 503 with a short retry hint. A shared filesystem must support `flock` and atomic rename. The integrity checks deliberately read source files; very large libraries need suitable hosting time and disk limits.

Only `abo/zip/.cache-v16/` is disposable. **Do not delete `abo/zip/`**, which also holds gig PDF attachments. Superseded archives are removed within a gig/type cache; directories of permanently removed gigs can be cleaned during maintenance, with no active downloads or administration writes.

## Final review — 31 October 2026

The published V15 tree was cloned afresh and compared with Main and V14. The final review found and corrected four further issues:

| Finding | Correction |
| --- | --- |
| Plain external tune links disappeared after the V15 scheme filter | Both plain HTTP(S)/mailto URLs and the established “Label: URL” format work; unsafe schemes remain blocked. Only the label is split, so nested URLs in query strings stay intact. |
| MP3 renaming checked a different name from the one it wrote | Collision checks now use the final normalised name, after removal of the duration. Existing recordings cannot be overwritten through that mismatch. Uppercase MP3 extensions work; symlink sources are rejected. |
| The gig editor could not reliably round-trip old Windows-1252 filenames through UTF-8 JSON | Display names are mapped back to their existing filesystem bytes. Saving gig information retains legacy setlist references, including missing tunes and repeated entries. Copy/archive/restore, PDF attachments, links and safety copies retain the original names. Ambiguous names are rejected before saving. Safety copies include `path_bytes` as base64 alongside the readable `path`. |
| Catalog badges missed bracket-containing tune folders and counted unusable files | Literal directory enumeration now reports actual readable, nonempty PDF/MP3 media, excluding deleted, dot-hidden and symlink files. |

Final verification: **557 checks passed**, comprising the original suites (with 30 admin DOM checks) and **33 additional HTTP review checks**, plus all **155 first-party PHP syntax checks** and a clean Composer audit. The new review tests reproduce the defects using disposable data and also check that malformed optional federation configuration does not disable local password login.

The fixes add no user actions and do not change V14 spacing or the rights model. No production data or real identity provider was accessed. Production-provider interoperability and hosting-specific behaviour still require an installation test; this review is not a guarantee against every possible defect.
